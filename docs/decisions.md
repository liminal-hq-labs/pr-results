# Decisions

Each decision is numbered and stays here even when superseded, with a note on what replaced it. Open questions move here once they are answered.

| # | Decision | Choice | Why |
|---|---|---|---|
| D1 | Home | A Liminal HQ Labs experiment in `liminal-hq-labs/pr-results`, public from the first commit | Try the idea in the open before it earns a place in Liminal HQ. Public is also what the Labs charter requires, and a private tool would complicate use from public repositories. Graduation to `liminal-hq` follows the charter's criteria |
| D2 | Licence | `Apache-2.0 OR MIT` | House licence, compatible with both ecosystems |
| D3 | Dependency updates | No Dependabot configuration until the project opts in | Labs repositories stay quiet by default. See the [Labs charter](https://github.com/liminal-hq-labs/.github/blob/main/docs/labs-charter.md#dependabot-is-opt-in). **Superseded by D12** |
| D4 | Name | `pr-results` for the repository, the command, the crates, the configuration file, the marker and the action | A plain description that is easy to find and says what the tool does |
| D5 | Language | Rust, one binary with a small, audited dependency set | The house language for tooling. Parsing untrusted XML and making the escaping rules total and testable is easier in Rust, and the same binary renders goldens locally with no network |
| D6 | Packaging | A statically linked musl binary per release, run by a thin composite action that carries the binary's SHA-256, plus a reusable workflow in this repository | Pinning the action by commit SHA also pins the exact binary, with a `build: source` fallback. A TypeScript action would ship a generated `dist/` that reviewers cannot meaningfully read, and a container action would pay a pull on every run and fail inside container jobs. Start-up figures are estimates |
| D7 | One comment, one check run per suite | A single sticky comment per pull request and comment key, and a check run per suite with annotations | Failures stay attributed and annotated while the pull request gets one summary instead of a comment per suite |
| D8 | Where it runs | A `workflow_run` publisher from the default branch | A fork's `pull_request` token is read-only. In-job publishing works only for same-repository pull requests and pushes, and the documentation says so |
| D9 | Configuration | `.github/pr-results.toml`, read from the default branch, with unknown keys an error and defaults that need no file for the usual artefact names | One small reviewed file replaces a dozen YAML inputs repeated per step, and a fork cannot change it |
| D10 | Escaping | Every untrusted string reaches the output through the `Safe` type, in one place | A published advisory about unescaped test names in another reporter's tables shows that escaping must be central, not per table |
| D11 | Pinning | Every action by full commit SHA with the version in a comment, and every container image by digest. No floating major tag for consumers either | Fixes the exact code a write-token workflow runs, and keeps diffs readable |
| D12 | Dependency updates (supersedes D3) | Dependabot on for `github-actions` weekly, and `cargo` weekly from the pull request that adds `Cargo.toml`, labels `ci` and `build` | A tool that holds write tokens should stay patched. The `cargo` entry waits for a manifest, because Dependabot reports a failed run when it finds none |
| D13 | Where the code starts | No crates, tests or `action.yml` until the code that needs them. The skeleton is documentation, the hero and the checks that exist today | Scaffolding written before the code that needs it drifts. The Rust jobs in `ci.yml` are commented, ready for the first crate |
| D14 | Where the reusable workflow lives | In this repository, versioned with the binary, not in `liminal-hq/.github` | The shared repository holds CI images and its workflow audit has an untriaged backlog. A privileged publisher there would couple its release cadence to the images |
| D15 | Release process | A release pull request records the binaries' digests in `action.yml`. A tagged build must reproduce them or fail. Tags only when the owner asks | Pinning by SHA needs the digest in the pinned commit. If builds prove not reproducible, a two-commit release is the fallback, recorded here |
| D16 | Exit status | `0` when it published, even if tests failed. Non-zero only when publishing itself failed | The check runs carry the test outcome. `--fail-on-failures` exists for local use |
| D17 | Dogfood | The tool's own publisher never runs the pull request's build. **Amended:** until v0.1.0 it runs the default branch's reviewed source: `publish-test-results.yml` is a `workflow_run` workflow (inert until it is on the default branch) that checks out the default branch with no credentials and runs `uses: ./` with `build: source`. A follow-up after the tag pins the latest release by SHA, as the original decision said | A pull request must not change the code that holds the write token. There is no release to pin before the first one, and the default branch holds only reviewed code, so the dogfood can prove the publisher on this repository's pull requests (and the sandbox gate) before the tag, without an unreviewed build. **Accepted risk:** the `build: source` step installs a toolchain and builds in a job that holds a write token. The token is not in the job's environment and only the action's final step receives it (`scripts/check-pins.sh` enforces that), but the compiler download and the dependencies' build scripts do run there until the follow-up pins the released binary. See the security guide |
| D18 | Approving reviews (was Q6) | `can_approve_pull_request_reviews` is `false` for this repository, already set | The workflows hold write tokens, and a workflow that can approve pull requests could approve its own changes. The reference repositories leave it on, which is not a reason to copy them |
| D19 | Crate layout (refines the component table in the specification) | `crates/pr-results-core` holds the model, `Safe` and the JUnit parsers, and `crates/pr-results` is the command line. `pr-results-render` and `pr-results-github` are added with the code that needs them | One library crate keeps the type that makes escaping total next to the model it protects, and splitting it later is cheap. The specification's separate `model` and `parse` crates added a boundary with nothing on either side of it |
| D20 | Dependencies in the first code | `quick-xml` `=0.42.0` with default features off (MIT), which brings `memchr` `2.8.3` (Unlicense OR MIT, taken as MIT). No `serde`, `serde_json`, `toml`, `clap` or logging crate yet. `deny.toml` allows MIT and Apache-2.0 only, from `crates.io` only, with no wildcards | Nothing yet reads or writes JSON or TOML, and the command line has two flags. Each crate arrives with the code that uses it, pinned exactly, and Dependabot's `cargo` ecosystem is on from this change (D12) |
| D21 | One type for untrusted text | Strings from a report are held as `Untrusted`, which has no `Display`. Output is built only from `Safe`, whose constructors are `text`, `code_block`, `log_line`, `workflow_data`, `workflow_property`, `trusted` (a `&'static str`, so a string built at run time cannot enter), `number`, `concat` and `join`. Every constructor that takes untrusted text takes a size budget | The renderer can then accept only `Safe`, and the compiler rejects a raw string. `Safe::link` arrived with the renderer, where the trusted URL parts exist (D33) |
| D22 | Escaping rules for Markdown text (Q9 stays open) | `Safe::text` writes the five HTML specials as entities, `@` as the fullwidth commercial at U+FF20 and every `#` as the fullwidth number sign U+FF03, backslash-escapes every Markdown special in `` \`*_{}[]()+-.!\|~=$ `` wherever it appears, turns line breaks and tabs into spaces, drops NUL and other controls, spells out bidirectional, zero-width, byte-order and other invisible characters as `\u{…}` (D29), writes the second of two colons and any colon before a slash as `&#58;`, and writes leading spaces as entities | Escaping everywhere is noisier in the source than escaping where syntax could start, but it is total and needs no context from the caller. Breaking `::` keeps a name from forming a workflow command if it is ever echoed, and breaking `://` with the escaped `.` in `www.` stops autolinks. Rust paths such as `a::b` still read normally once rendered. **Revised:** the first version wrote `@` and `#` as the entities `&#64;` and `&#35;`. That was dropped because the entities are probably decoded back to `@` and `#` before GitHub's mention and cross-reference filters run (the gh-aw project decodes entities before its own mention filtering for exactly that reason), and nothing from GitHub says the entity is safe. The fullwidth forms depend on no decoding, are visible, and are not parsed as a mention or an issue reference, but that is **not verified** either: a sandbox test with the owner's own account must still precede the renderer (Q9). A hyphen between a letter or digit and a digit (`GH-123`, `ABC-123`) is written as the fullwidth hyphen-minus U+FF0D, because a backslash escape is decoded before GitHub's reference filter runs, for the same reason as the entities. `org/repo#123`, `@org/team`, `@everyone` and `GH-123` all stop looking like references. The documented-safe route is code formatting, which GitHub does not scan for mentions (D32), so the renderer is to put names, paths and failure text in `code_span` or `code_block`, and `text` is for the fixed words around them. Emoji shortcodes such as `:smile:` are not neutralised, which is cosmetic |
| D23 | Truncation | A budget counts characters after escaping, so a cut never lands inside an escape. A cut ends with `… (N more characters omitted)`, outside the budget, and `N` includes characters already cut at parse time. `Untrusted` remembers how many it lost | Cutting is always visible and the marker is made of digits and fixed words, so it needs no escaping |
| D24 | Parser limits and errors | The input is at most 50 MiB, nesting at most 64 elements, at most 200 000 cases, at most 10 000 suites (D28), 256 attributes per element and 100 attempts per case. Names, class names and paths are capped at 1 KiB, messages at 1 KiB, bodies and captured output at 16 KiB, while streaming. A document type, an entity other than the five predefined ones and numeric references, a NUL, an encoding other than UTF-8, a second root and text outside the root are errors. Invalid UTF-8 is replaced, and all kept text is budgeted (D30). Errors name the problem and never quote the input. A `time` or `line` that is not plain digits counts as zero or absent instead of failing the file | The limits are the specification's. Timing is informational, and JUnit writers from other locales write commas, so failing a whole file for it would hide real results. A message that quotes the input would carry hostile text into logs |
| D25 | Reading JUnit | A failure or error wins over a skip. A case is flaky when it has no failure, error or skip and at least one failed attempt (`flakyFailure`, `flakyError`). `rerunFailure` and `rerunError` are attempts of a case that stays failed. Nested `testsuite` elements flatten into their top-level suite, whose `time` is the suite's time. A suite with no `time` sums its cases. `Report::merge_same_named` merges suites that share a name and flavour | The cheapest reading that never hides a failure, and it matches how nextest, bun and the step contract nest and retry |
| D26 | Locations | A case's file and line come from `file` and `line` attributes (a suite's `file` is inherited), then by flavour: Rust panic text for nextest, the class name or suite name for vitest, and the part of the class name before ` › ` for Playwright. A path must be relative and free of `..`, drive letters, URLs and control characters, or it is dropped. JavaScript stack frames are read for the four JavaScript flavours, and `suite.path_prefix` is put in front of every path (D63) | A path from a report can never name a place outside the repository, and a missing location only means no annotation |
| D27 | Fixtures and CI for this code | The fixtures are written by hand from each reporter's documented format, not captured, and the nextest ones were checked against the shape nextest 0.9.151 writes for this repository's own tests. **Amended by D63:** the vitest, bun, jest-junit and Playwright fixtures `real-*.xml` are real output, and what each reporter records about retries was read from it; the hand-written ones stay as extra shapes. CI gains Format, Clippy and Tests jobs in the pinned `ci-rust` image, which carries `cargo-nextest`. The `ci` profile retries once, so flaky tests reach the JUnit. Uploading the results and the dependency policy job wait for the pinned upload action and the first release | The jobs reuse the pins the skeleton already named. Retrying once makes the tool's own JUnit exercise the `flakyFailure` path that its parsers read |
| D28 | Suite limit and merge cost | `Limits::max_suites` is 10 000, and a document with more suites is refused with an error that names the limit. `Report::merge_same_named` finds each suite through an ordered map keyed on name and flavour | A linear scan per suite made 100 000 distinct suites cost 11 s, which is a way to stall the publisher with a small file. An ordered map gives n log n work and a result that does not depend on hashing. Refusing, like the case limit, is visible and counted, where silently dropping suites would hide results |
| D29 | Invisible characters | `Safe` spells out as `\u{…}` every character in the Unicode category `Cf`, every `Default_Ignorable_Code_Point` (including the unassigned ones inside those blocks) and the object replacement character: the tag block, variation selectors, the soft hyphen, the combining grapheme joiner, the deprecated format characters, the interlinear annotation marks and the Hangul fillers, besides the bidirectional, zero-width and byte-order characters of D22. The table is written by hand from Unicode 15.1. It also covers the blanks: the `Zs` spaces other than U+0020, and the Braille blank U+2800, which make two names look the same. U+200C and U+200D are spelled out too | Characters that draw nothing can hide text (tag characters carry a whole hidden message), and a name that looks like another name is a way to spoof results. Showing them is the safe direction, and the cost is a visible code point in a name that uses a joiner for a script or an emoji sequence. A hand-written table avoids a Unicode data dependency, and being wider than the properties is deliberate |
| D30 | Memory budget | `Untrusted` shares its text, so a suite's `file` is stored once and cases inherit it, and a path taken from a suite name is stored once. `Limits::max_text_bytes` is 64 MiB for what the report keeps in memory: all kept text, counted once per stored copy and after invalid UTF-8 is replaced (U+FFFD is three bytes per bad byte), plus a fixed overhead of 40 bytes per piece of text, 64 per case and 64 per kept attempt. Bodies are counted even when a case does not keep them. `max_bytes` applies to the input before and after replacement. Over budget is refused with an error that names the limit | Copying a 1 KiB `file` into 200 000 cases turned a 7.7 MiB input into 273 MiB resident. Counting stored copies, not input bytes, is what bounds memory, and counting after replacement closes the tripling. 200 000 cases with a long suite `file` now peak at 64 MiB (release build, `VmHWM`). Counting text alone was not enough: 32 027 cases with 100 empty `<flakyFailure/>` each (49 MB of input) kept 3.2 million attempts and peaked at 285 MiB, because an attempt with no text cost nothing. That input is now refused, and it peaks at 108 MiB with the 49 MB input itself resident. The budget bounds what the report holds, not the input or the parser's transient state, which `max_bytes` and the streaming reader bound |
| D31 | Attempts past the limit | Attempts beyond `max_attempts` are counted in `Case::attempts_omitted`, and a renderer must show the count whenever it is not zero | D23 says truncation is always visible. A dropped retry with no count is a silent cut. The renderer shows it for every failure and every flaky test (D33) |
| D32 | Inline code for names | `Safe::code_span` writes inline code on one line: the delimiter is one backtick longer than the longest run in the content, padded with a space when the content starts or ends with a backtick, line breaks (LF, CR, NEL, line and paragraph separators) become `⏎` while tab, vertical tab and form feed become a space, a pipe is written `\|` for table cells, empty content is a space, and a cut follows the same visible marker as the other constructors. The renderer is to use it for test names, file paths and anything else a reader needs to see exactly, and `code_block` (unchanged, adaptive fence) for failure text | GitHub documents that mentions are not looked for in code, which makes code the one route that does not depend on how entities or lookalike characters are filtered. It also shows a name exactly as written |
| D33 | The renderer and the trusted values | `pr-results-render` holds the comment, the check runs and the annotations and takes the model and `Safe` only. The values a renderer needs live in `pr-results-core/src/trusted.rs`: `Sha` (40 lowercase hex digits), `RepoSlug`, `RunId`, `CommentKey` (`[a-z0-9][a-z0-9-]{0,31}`), `ServerUrl` (`https://host[:port]` and nothing else), `RepoPath` (the D26 rules, and nothing that draws blank), `TrustedUrl` (only `commit`, `run` and `run_artifacts`, from checked parts) and `Marker` (`parse` accepts exactly what `render` writes, `prefix_matches` finds a comment by key). `Safe` gains `link`, `grouped` (thin-space groups: `1 978`), `duration_ms` (`0.4 s`, `18.2 s`, `1 m 47 s`, `2 h 5 m`), `sha_short`, `path`, `plain_text`, `plain_block` and `after_first_line` | `Safe`'s field is private, so the parts that build it from checked values must be in its crate. A link can then be made only from a `TrustedUrl`, which has no constructor from a string, and a forged marker is never mistaken for ours. Annotations are not Markdown (documented GitHub behaviour, not verified here), so their title and message are plain text with controls dropped and invisible characters spelled out |
| D34 | Raw HTML lines hold only trusted words and numbers | `<details>`, `<summary>` and `</details>` are written from literals and counts. A name goes on a Markdown line of its own, after a blank line, in a code span. The adoption guide's mock is corrected to match | Markdown inside a raw HTML line is not rendered, so the first mock's `<summary><code>name</code></summary>` showed literally, and putting escaped text in HTML would have meant a second escaping path. Keeping untrusted text out of every HTML line means `Safe` has nothing to get wrong there |
| D35 | Two shapes of step results | The `steps` renderer reads both a `<testsuite>` per group (the specification's contract) and a `<testsuite>` per job with `classname="check.GROUP"`, `<failure type="step">` holding the last 80 lines and no skipped steps (Desk's converter, from its plan). The group is what follows the last colon of the class name, or failing that its last full stop, and is left out when it repeats the suite's name. A step's excerpt is the last lines of its log, and a test's is the first lines of its failure. The contract now says "per group or per job". `tests/fixtures/steps/desk-job.xml` holds the second shape | Desk's converter was planned after the contract was written and chose one suite per job. Reading both costs a few lines and lets neither side change for the other. The end of a log is where a step failed, where the start of a panic message is where a test failed |
| D36 | A section is the unit | The renderer's unit is a section: one configured suite, one check run, one row of the table, holding every `<testsuite>` read for it. Desk needs a configuration file, because its artefacts are `results-<job>` holding `steps.xml` and `nextest-*.xml`, which the `*-test-results*` default misses, and one configured suite spans many artefacts and many `<testsuite>` elements | The first design assumed one artefact, one file, one suite. Desk's CI shows a suite is what a product calls it, not what a reporter wrote |
| D37 | Size budget details | A size is the larger of a text's characters and its UTF-16 units. The degradation steps run in the order of the specification, each adds a line saying what was left out, and a step that would change nothing is not taken, so `steps_taken` lists only what happened. `max_failures` is the cap from the start, the `Failures20` step caps at 20 only if it was set higher, and the last step is the marker, heading, totals and footer. A check run's text is filled failure by failure and ends with the slowest ten. Over a limit that even the last step cannot meet, the last step is returned as it is | GitHub's length counting is not verified, so staying under it in both measures is the cheap defence. Cutting by whole failures keeps every block well formed, where cutting text could leave a `<details>` open |
| D38 | First adopter (answers Q5) | Desk first, after this repository's own dogfood. Its CI already produces `results-*`, `event-file` and step JUnit. After v0.1.0 a small pull request in Desk swaps its current reporter steps for the reusable workflow and a `pr-results.toml` | Desk is what the must-haves describe, and a product that already publishes through `workflow_run` is the quicker proof |
| D39 | Default-branch pushes (answers Q8) | Yes: a push to the default branch gets check runs and no comment | It is cheap, it is per commit, and it is what Desk's CI expects |
| D40 | The step converter (answers Q10) | A shell-step product keeps its converter, which Desk plans to write in Rust. `pr-results` does not read `CHECK_TIMES` in v0.1 | One reader of one well-defined format is less to maintain than two |
| D41 | Pinning and branch protection (answers Q11) | Yes to both, done by the owner. After the first release, `sha_pinning_required` is turned on for the repository's Actions permissions. After two green weeks, a ruleset on `main` requires a pull request, forbids force pushes and requires the checks `Format`, `Clippy`, `Tests`, `Goldens`, `Dependency policy` and `Workflow audit` | Both need checks that have already run before they can be named as required. Neither is a setting an agent changes |
| D42 | Fragments never join into a reference | Every line of the renderer is joined by `cat`, which puts a space between two fragments that would form a letter or digit, an optional backslash, a hyphen and a digit across the join. A test fails if the renderer calls `Safe::concat` or `Safe::join` anywhere else, or `Safe::text` anywhere but the heading's title | `Safe::text` breaks `GH-123` inside one fragment, but `Safe::concat` can build it from `GH` and `-123`, and each piece is safe alone. Putting the rule in the one join the renderer uses means no line can forget it |
| D43 | Q9 gate result for the renderer | The probe (`mention_probe`, before it gained the heading and pipe rows) was posted as a comment in a throwaway private repository in `liminal-hq-labs`, since deleted, through the REST API as the owner's account (the token lacked the `workflow` scope, so not as `github-actions[bot]`), edited with a PATCH of the same body, and read back as `body_html`. **Raw control rows:** `@ScottMorris` and `@everyone` became `user-mention` anchors, `#1` an `issue-link`, `GH-1` an `issue-link` to issue 1 (the `GH-` autolink reference was configured to point at `https://example.invalid/<num>`, yet the anchor points at the issue, so `GH-1` is read as an issue reference), and `https://example.invalid/probe` and `www.example.invalid` plain autolinks. `@ScottMorris/probe-team` (no such team) and `ScottMorris/mention-probe-sandbox#1` (a repository that did not exist under that owner) made no anchor, so those two controls are **inconclusive**. **Renderer forms:** `text` (fullwidth `＠`, `＃`, `GH－1`, `https&#58;//`, `www\.`), `code_span` and `code_block` rows made no anchor at all, and in the failure layout the only anchors were the trusted footer links (commit, run, artefacts). **Not tested:** notifications (a self-mention does not notify the author, and a bot author was not tried), `@team` mentions of a real team, cross-repository references to a real repository, annotations, check-run text, the heading and table cells holding pipes. The manual gate for the renderer is satisfied for what it emits today. The untested items are follow-ups for v0.2 | The gate was meant to be run against GitHub, not argued. A control that fires shows the probe can see an anchor, so the zero counts mean something. An account that is not the author is needed to see notifications, and a real team and repository are needed for the two inconclusive controls. Nothing here shows that `text` is safe in every position, only that the forms the renderer emits did not link |
| D44 | HTTP client and its dependencies | `ureq` `=3.5.1` with default features off and `rustls` on (MIT OR Apache-2.0), which brings `rustls` (Apache-2.0 OR ISC OR MIT) with the `ring` provider (`ring` is Apache-2.0 AND ISC; `untrusted` ISC; `rustls-webpki` ISC), `subtle` (BSD-3-Clause), `webpki-roots` (CDLA-Permissive-2.0, the Mozilla roots as data) and `ureq-proto`, `http`, `httparse`, `bytes`, `base64`, `percent-encoding`, `log`, `utf8-zero`, `once_cell`, `zeroize`, `rustls-pki-types`, `cfg-if`, `getrandom`, `libc` and, for `ring`'s build, `cc`, `shlex` and `find-msvc-tools` (all MIT OR Apache-2.0 or MIT). `serde_json` `=1.0.154` (MIT OR Apache-2.0) with `std` only, which brings `serde_core`, `itoa`, `zmij` (MIT) and the `memchr` already in. `miniz_oxide` `=0.9.1` with `with-alloc` (MIT OR Zlib OR Apache-2.0) and `adler2` (0BSD OR MIT OR Apache-2.0). The `serde` crate and its `derive` are not used: requests are built with `json!` and responses are read as `Value`, which keeps `syn` and its siblings out. `cargo tree -e features` shows `ring` and no `aws-lc`. `deny.toml` gains ISC (`ring`, `rustls-webpki`, `untrusted`), BSD-3-Clause (`subtle`) and CDLA-Permissive-2.0 (`webpki-roots`); no crate in the graph needs Unicode-3.0, so it is not allowed. Numbers, release build with the default profile and no link-time optimization: the external crates in `cargo tree` go from 2 (`quick-xml`, `memchr`) to 32, and a stripped binary that links the whole client goes from 363 352 bytes (the command line today, which does not yet use the core) to 3 078 672. That is more than the 25 crates and 2 MB first expected, and the release profile (`lto`, `codegen-units = 1`, `opt-level = "z"`, `panic = "abort"`) is not yet tuned | `gh api` costs no crates but varies by runner, is often missing in containers and hides statuses and redirect handling, which the token rules depend on. `ureq` is synchronous, so there is no async runtime, and `rustls` with `ring` needs no OpenSSL and links statically for the musl release. `ring` brings C and assembly, which is the risk accepted. The `ring` provider was chosen over `aws-lc-rs` because it needs no CMake or C++ toolchain. Each crate is pinned exactly where it is a direct dependency; the rest are pinned by `Cargo.lock`, which CI builds with `--locked` |
| D45 | The zip reader | Our own, on `miniz_oxide`, not the `zip` crate. It reads the central directory only, with a bounded search for the end record, and takes stored and deflated entries. It refuses zip64, encryption, other methods, split archives, absolute, `..`, backslash, drive-letter, control-character, empty, repeated and non-UTF-8 names, duplicate names, links, devices and directories that hold data, offsets outside the archive or into the directory, a local header whose name differs from the directory's, more than `max_files` entries, and entries or totals over the byte limits. It checks CRC-32 and inflates only to the declared size plus one byte. A directory entry counts as a file and is not returned. `read_zip_filtered` inflates and counts only the files a predicate accepts, still checking every name. The publisher reads one artefact at a time, keeps only the entries some section's file globs match, parses them and drops the archive before the next download, and caps the inflated bytes kept across the whole run at `archive.max_total_bytes` (the room left is passed into the reader), because a 102 KB zip can inflate to 100 MiB and a fork can upload many. The `size + 1` bound is pinned by a test that reads the size of the buffer the inflater had grown to | `upload-artifact` writes only stored and deflated entries, and the `zip` crate has many codecs and a history of yanks for a format where two methods matter. An end record that is a look-alike placed last in the comment is found first, as in any reader that searches from the end, and is refused because it describes no directory, so a hostile archive can only make us reject it |
| D46 | Where the token goes | The token is added in `UreqForge::send` and nowhere else, to a URL made of the API base and an `ApiPath`. An `ApiPath` holds only the characters of a path and a query, never `..`, an empty segment, `#`, a percent-encoded dot or slash, or a host. A `Link: rel="next"` is taken only if it begins with the API base exactly and what follows parses as an `ApiPath`. The library follows no redirect. The artefact download's 302 is read as a `BlobUrl` (`https://`, a host, no user information, no spaces) and fetched by `fetch_blob` with no `Authorization` header, following at most three further redirects, each to another `https://` URL. A redirect to `http://` is refused. Errors are fixed phrases, never the library's own text, which can quote a URL. `Token` has a redacted `Debug` and no `Display`. `fetch_blob` also checks the host of every hop against an allowlist before sending anything: `*.blob.core.windows.net` and `*.githubusercontent.com` for `api.github.com` (they cover `productionresultssa*` storage and `pipelines.actions.githubusercontent.com`), the API host alone for any other base, and `UreqForge::with_blob_hosts` for a GitHub Enterprise Server whose storage is elsewhere. A `*.suffix` entry needs a label before the suffix, and an IP address matches only if listed | A presigned blob URL carries its own permission and must not learn the token, and a paging link in a response must not be a way to send it elsewhere. Making the two URLs different types means a call that would mix them does not compile |
| D47 | The publish flow | The artefacts are read and rendered first, then the check runs are written, then the comment, so a refused comment (a read-only token, a locked conversation) still leaves the checks posted and sets the exit status. ### What current reporting taught

- **Two patterns, both partial.** Reporting in the test job is simple and fails on forks and Dependabot, where the token is read-only. The `workflow_run` publisher is correct and is copied from repository to repository, so a fix lands in one copy.
- **One comment per suite** adds up quickly: a pull request with four suites gets four comments, and a job-status comment can come on top.
- **Artefact names are already consistent** across the products this tool is for: `rust-test-results`, `frontend-test-results` or `js-test-results`, `language-test-results`, `mcp-test-results`, and an `event-file` artefact holding the event. Defaulting to them means adoption needs no CI change beyond the publisher.
- **JUnit is everywhere except shell-step projects**, which need a converter or a step format of their own.
- **Where a poster builds its own Markdown** the usual gaps are unescaped test names, code fences that a failure message can break, trusting a pull request number from an artefact a fork controls, and finding its own comment by prefix with no author check. Each has a rule in the specification.
- **Pins are usually tags.** Pinning a reporter by a moving tag trusts the tag not to be retargeted, so this repository pins by full SHA and its documentation models it.
- **JUnit files carry the runner's hostname.** It is never rendered.

### What this tool does differently

- One comment per pull request and a check run per suite.
- A house layout: calm, text-first, Canadian English, no emoji wall, collapsed detail, failures first, passing suites in one line each.
- Flexibility per product: custom check names, suites mapped from artefact names, shell-step results as first-class suites, an optional combined check, and links to the run, its artefacts and the job summary.
- Configuration in a small file in each repository, read from the default branch.
- Security by construction: every untrusted string escaped by one type, verified pull request numbers, author-checked markers, strict size budgets, no secrets and minimal permissions.
- Comparison against the base branch that does not depend on check-run annotations, which break when check names change.

## Risks

- **Graduation and pins.** Transferring the repository to `liminal-hq` changes the `uses:` path. Whether Actions follows the redirect for a transferred repository was not verified, so plan to update consumers' pins in the same wave.
- **Check-run placement.** Check runs from `GITHUB_TOKEN` can appear under the publisher workflow in the UI. This is cosmetic and shared by every option.
- **Artefact retention.** Baselines come from base-branch artefacts, which expire (90 days by default, less if the repository sets it). A quiet repository may have no baseline, and the comment then omits the column.
- **Reproducible builds** may not hold across Rust or image updates. The fallback release process exists.
- **Comment edit history** keeps every previous version visible to anyone, including content that was later escaped better, so escaping must be right from the first release.
- **Rate limits** on large monorepos with many annotations, mitigated by batching and the per-suite cap.
- **Scope creep** towards a dashboard. The non-goals hold the line.
